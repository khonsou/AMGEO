5. Agent 直接执行、核验并交付

运行链路：采集 / 事实 / 实体 Agent 并行 → 内容与 Patch Agent → QA Agent 自动测试 → 工程 / 发布 Agent 应用允许的改动 → 浏览器 / API Agent 采样 → 分析 Agent 更新任务。

不把例行抓取、后台导出、写稿、翻译、改代码、测试和上线后核对分配给人。已有访问与授权范围内连续执行；缺仓库、连接、可信原始数据时仅阻塞相应动作，其他分支继续。

  1. 采集 / 诊断 Agent交付时间戳、响应、HTML/DOM、差异与机器验收。接入实际仓库后定位路由、修改真实文件、构建并生成补丁。无仓库时清楚标记“修复未应用”，不猜框架。
  2. 事实 / 实体 Agent把型号、版本、市场、单位与逐条证据组成事实账本。37g/39g 等冲突无法裁决时冻结该字段并从待发布稿中省略；本次已执行该降级。
  3. 内容 / 本地化 Agent产出有依据的中英文正文、元数据和修改操作。当前已生成两份换电说明与13项离线修改，不把尚无实测的数据写进稿件。
  4. QA Agent校验来源片段、hash、数值、实体、语言、修改前置条件与回滚，并在实际工程环境中运行链接/schema/渲染回归。独立核验与确定性检查配合；不把模型自评分当事实证明。
  5. 发布 Agent读取当前源对象，映射到真实CMS字段或源码，按已有范围写入并read-back；失败回滚。离线公开HTML修改不等于Shopify mutation；当前未接入CMS和源站，无实际发布。
  6. 测量 / 分析 Agent用已授权浏览器采样消费端，以官方API运行独立实验；原文、来源、费用和版本全部归档，自动计算结果并生成下一批任务。

执行层新增推荐：独立服务用 OpenHands SDK；GitHub仓库内用 gh-aw。需要UI操作时用 browser-use，稳定回归用 Playwright。实际组件边界、今日快照和完整任务契约见 Agent执行方案。

第二层：固定问题面板

随附 48 条未运行种子题：每语言 24 条，含 12 鼠标、8 键盘、4 购买 / 支持；每语言 18 条非品牌与 6 条品牌。先用客户问题与搜索数据复核，锁定版本，不能每周只保留品牌表现好的题。

API 另设实验表：英文可用联网 provider 做 24 题 × 3 provider × 3 次＝216 次 / 轮；中文可接明确支持 Search / Fetch 的官方接口，记录检索与最终生成步骤。预算不足先缩减 provider 数量，保持固定题组。API 测量不与消费端合并，不把自建 RAG 回答当平台推荐份额。

四个核心指标分别计算，不汇成神秘总分：

  • 品牌提及率＝包含品牌 / 正确产品实体的测试次数 ÷ 成功完成的固定题测试次数。
  • 官网引用率＝引用已确认官方域名的测试次数 ÷ 成功完成的固定题测试次数；引用第三方对品牌的评测另列。
  • 适配推荐率＝明确将正确产品作为适合该需求选项的测试次数 ÷ 成功完成的固定题测试次数。无依据的“最强”不算优质结果。
  • 事实正确率＝抽查正确且有依据的关键事实断言数 ÷ 被抽查关键事实断言数；关键参数冲突、错型号、过期发货和错误价格另设错误清单。

网络错误 / 限流等排除出成功测试分母但单报失败率；成功完成测试但未出现 AI 回答计零并单列。未联网、无引用和未触发搜索的答案也保留在端到端分母，另报“有 AI 回答条件下”的比例，避免挑样本。非品牌测试不向 system prompt 注入品牌或官网。多次生成不是独立消费者；需要区间时按问题聚类估计，不虚报统计显著性。

2. SEO 与 GEO 的实践边界

SEO 解决搜索发现、索引与高意图到站；GEO 在此基础上关注回答中的提及、引用、推荐和事实准确性。两者共同依赖可靠资料与可访问页面。Google 官方明确，AI 搜索仍遵循 SEO 基础，没有专用的 GEO schema；llms.txt 不影响 Google 搜索可见度。Google AI 优化指南。

适合 Angry Miao 的最佳实践是：把原创测试、设计解释、版本区别、适配边界和售后事实做成可持续维护的资料；用清晰的标题、对比与图示帮助用户选择。结论段或 FAQ 可以提高阅读效率，但不存在“固定字数答案块必然被 AI 引用”的保证。

避免把同一文章改写成几百个手型、游戏名、价格词页面。Google 的 scaled content abuse 政策针对主要为操纵排名而大量生产、缺乏增量价值的内容；AI 辅助内容及元数据也需发布前核验。Spam policies、使用生成式 AI 内容。

需要纠正三类常见旧建议：

  • Google FAQ 富结果已于 2026-05-07 停止展示；保留真实 FAQ 是为了用户与支持，不应据此承诺富结果。官方更新记录。
  • IndexNow 是参与引擎的更新通知，当前参与列表不含 Google；普通商品页也不适用 Google 的 JobPosting / BroadcastEvent Indexing API。参与方、Indexing API 范围。
  • GEO 论文在特定基准上的最高提升，不能转写为 Angry Miao 的销售或流量预期。原始 GEO 研究。

搜索 bot 与训练 bot 应分别配置：OAI-SearchBot 与 GPTBot 用途不同；PerplexityBot 另有官方规则。核对 robots、CDN / WAF 和官方来源验证；允许抓取并不保证被引用。OpenAI bots、Perplexity crawlers。

2. SEO 与 GEO 的实践边界

SEO 解决搜索发现、索引与高意图到站；GEO 在此基础上关注回答中的提及、引用、推荐和事实准确性。两者共同依赖可靠资料与可访问页面。Google 官方明确，AI 搜索仍遵循 SEO 基础，没有专用的 GEO schema；llms.txt 不影响 Google 搜索可见度。Google AI 优化指南。

适合 Angry Miao 的最佳实践是：把原创测试、设计解释、版本区别、适配边界和售后事实做成可持续维护的资料；用清晰的标题、对比与图示帮助用户选择。结论段或 FAQ 可以提高阅读效率，但不存在“固定字数答案块必然被 AI 引用”的保证。

避免把同一文章改写成几百个手型、游戏名、价格词页面。Google 的 scaled content abuse 政策针对主要为操纵排名而大量生产、缺乏增量价值的内容；AI 辅助内容及元数据也需发布前核验。Spam policies、使用生成式 AI 内容。

需要纠正三类常见旧建议：

  • Google FAQ 富结果已于 2026-05-07 停止展示；保留真实 FAQ 是为了用户与支持，不应据此承诺富结果。官方更新记录。
  • IndexNow 是参与引擎的更新通知，当前参与列表不含 Google；普通商品页也不适用 Google 的 JobPosting / BroadcastEvent Indexing API。参与方、Indexing API 范围。
  • GEO 论文在特定基准上的最高提升，不能转写为 Angry Miao 的销售或流量预期。原始 GEO 研究。

搜索 bot 与训练 bot 应分别配置：OAI-SearchBot 与 GPTBot 用途不同；PerplexityBot 另有官方规则。核对 robots、CDN / WAF 和官方来源验证；允许抓取并不保证被引用。OpenAI bots、Perplexity crawlers。
