# Angry Miao SEO/GEO 优化循环

每轮选一个能被验证的改变。写清目标市场、产品版本、用户问题、要改的页面或渠道、拟观察的指标和失败后怎么处理。围绕 AM Infinity Mouse 电竞鼠标与 CYBERBOARD R6 等 AI device 安排任务。[品牌上下文](../../config/brand-context.json)

## 从哪里继续

先读当前轮次、策略快照、待验收任务和上轮复盘。工作台的“按新策略开始下一轮”会关联上一轮。项目 Agent 也可使用现有工作流交接已执行的任务。查明所选周期、任务和验证记录后再开始，保留实际来源日期和本轮运行时间。[使用指南](../../docs/usage.md)

## 五道 Gate

Gate 是一道有证据要求的放行条件。每道 Gate 只决定对应任务能否进入下一个状态。遇到依赖时记录缺什么、已有证据和恢复条件，继续可独立执行的工作。

1. **立项。** 把观测定位到来源、日期、产品／版本、市场和渠道。查找选购、替代、操作、事实四类问题中的缺口，合并意图相同的题。生成包含目标、具体动作和验收条件的任务。需求假设可以进入调研；引用、价格、性能等具体主张必须有匹配证据才能进入对外文案。冲突只隔离对应字段，例如 .97 有线重量的 37g/39g。问题测试沿用[独立测试 Skill](../geo-question-eval/SKILL.md)。
2. **产物验收。** Agent 交付实际页面草稿、可应用修改或分析结果，保留内容摘要、来源和版本／哈希。独立复核人或 Agent 对照每条验收条件检查产物。通过后记录通过范围；退回时指出具体字段和证据。网站检查关注 HTML 能否直接回答问题，图表是否有文字等价，外部评测是否支持有关主张。可选 Markdown 与 HTML 须一致。Todo 勾选只记录执行，HTTP 429 表示本次采集受限，应保留状态码并择时重采。[网站扫描口径](../../docs/agent-readable-method.md)
3. **发布。** 对需要上线的修改，核实授权、真实源码或 CMS 对象、当前版本及回滚办法。在授权范围内应用后，回读线上目标 URL／对象，记录发布版本、时间和结果。缺部署能力时可以停在“本地草稿已验收”，发布 Gate 保持待满足。研究或诊断任务可在其声明的范围内结束。
4. **效果复测。** 发布前冻结中英文题组、市场、模型／搜索平台、联网模式、设置、评分口径与分母；待更新可被检索后，按同一协议复测。SEO 取搜索平台展现、点击或固定 SERP 记录；GEO 取真实回答，分别判断品牌提及、适配推荐、事实正确和最终答案引用 URL。品牌题与中立发现题分组。抓取日志、AI 引荐会话、未联网 API 基线各自保存。无 AI 回答的已完成题记零，调用错误和未执行项单列。协议或覆盖变化时另开基线。有可比差值仍需考虑平台更新、同期活动及未改动的对照问题。[测量规范](../../docs/measurement.md)
5. **策略采纳。** 给每条经验写明轮次、任务或指标字段、证据能支持的结论、下轮改变及复验条件。可复核的执行问题可形成下一版流程规则；某项内容“可能提高推荐率”保留为效果假设。记录负面或无变化结果，再决定保留、调整或回退。下一轮继承策略版本并用原协议检验预测。长期修改本 Skill 时，提供触发该修改的真实案例和回归验证，再通过项目版本管理更新。

## 闭环的两个落点

- **执行闭环**落实到证据、任务、交付、验收、复盘和下一轮输入。已有证据足以改进流程时，即使站点尚待发布也能推进。
- **效果闭环**落实到基线、已发布变更、线上回读、可比复测、策略决策及后续验证。仅当证据满足相应范围时，才报告观察到的变化或归因结论。

每次汇报给出已到哪道 Gate、可点开的证据、尚待满足的条件和下一步。呈现版本化策略与待测假设，把持续增加版本号或题数排除在效果指标之外。
