# AM SEO

面向特定品牌、能够持续监测与优化搜索及 AI 推荐表现，并与人类团队协同执行的 Agent 项目。**Angry Miao / 怒喵的中英双市场是首个实践实例。**

**使用入口：[打开 AM SEO 工作台](http://127.0.0.1:8787/)**。本机服务运行后，日常操作在浏览器完成。

## 使命

把针对品牌的 SEO / GEO 最佳实践，建设成一个以真实证据驱动的持续工作闭环：自动观察品牌在哪里被发现、如何被描述和推荐，发现问题与机会，执行优化，验证结果，再改进下一轮的方法和执行过程。

我们希望品牌在适合自己的用户需求中，被准确发现、正确理解、有依据地推荐，并让用户顺利完成选择、购买和使用。项目围绕品牌目标组织工作，网站、内容、商品数据与工具都是实现这些目标的组成部分。

**当前入口是分组 Todo + 问题测试 Skill。** 评分以浮窗显示；AI 流量来源设置合并到 Todo。品牌资料、连接和历史证据放在 Settings。

## 快速使用

打开 [工作台](http://127.0.0.1:8787/#todo) 后：

1. 在 **优化 Todo** 展开具体任务、准备与预览产物；勾选执行完成，并查看独立的验证结果。
2. 在 **问题测试** 输入产品，运行 Skill 生成中英四类问题、逐题独立回答并评估品牌 / 产品命中。可把选中问题转成 Todo。
3. 在右下角 **GEO 浮窗** 查看新 API 测试或历史联网 Agent 结果；原题组可再次测试。
4. 在 **AI 流量归因 Todo** 设置来源、导入带站点与时间范围的 GA4 聚合报表，记录会话和关键事件。

模型 key 由本机 Keychain 或进程内存持有，不进入仓库、日志或浏览器存储。DeepSeek 连接已支持；基础 API 回答不带联网搜索。发现题与品牌题、不同模型和协议分别统计。空回答计零，错误与未运行题不冒充有效样本。

已准备的交互页面为本地草稿，真实发布仍取决于站点连接。人的完整操作见 [使用指南](docs/usage.md)，执行 Skill 见 [geo-question-eval](skills/geo-question-eval/SKILL.md)。

## 目标与覆盖范围

SEO 关注品牌、产品及相关内容在搜索中的发现与匹配；GEO 关注它们在生成式回答中的呈现、引用与适配推荐。两者共同服务于品牌的真实业务结果。

优化范围覆盖用户的完整发现与决策过程：

- **搜索与 AI 入口**：搜索引擎、AI 搜索和问答产品中的品牌与非品牌需求，以及不同语言、地区和使用场景。
- **独立证据与讨论**：专业评测、视频、社区、用户体验和媒体内容，理解哪些信息影响品牌认知、哪些事实被引用或误读。
- **商品与渠道数据**：商品目录、feed、商城、经销渠道中的型号、规格、价格、库存、购买与售后信息。
- **自有品牌资产**：官网、商店、研发与设计内容、说明书、固件和支持资料，提供可控且可核验的信息与服务。

自有资产可以直接维护；渠道内容按实际授权修改；第三方内容主要通过观察、引用、证据供给和明确授权的沟通协作改善。独立评测和用户判断由真实体验产生，不能由 Agent 编造。

对 Angry Miao，以 **Future Art Community / 未来艺术社区** 为品牌表达背景，当前核心产品主线按用户最新定义为 **电竞鼠标 AM Infinity Mouse 与 AI device（例如 CYBERBOARD R6）**。针对编程极客、审美收藏家、潮流尝鲜者，分别研究电竞与AI工作流、设计与工艺、发售与社区参与的需求。AI device 的具体功能需另核实，不能从名称推断。中英市场共享事实源，分别维护需求、渠道、商业政策与测量基线。

## 方法论：从观察到验证的闭环

1. **建立品牌上下文。**明确定位、目标用户、适合与不适合的需求、市场、产品实体、权威事实、业务目标、可用连接和执行范围。
2. **持续监测真实表现。**维护稳定的问题与场景面板，采集搜索结果、AI 回答、实际引用来源、商品数据和业务观测；保留原文、时间、平台、语言与版本。
3. **定位问题与机会。**区分未被发现、被错误描述、证据不足、推荐不适配、商品数据过期及购买或支持障碍，追溯到可检查的来源与机制。
4. **提出可检验的优化假设。**说明面向哪个需求、改变什么、为什么可能有效、预期观察什么，以影响、证据、成本和执行条件解释优先级。
5. **执行具体改进。**更新事实与商品数据、完善内容及支持资料、准备评测素材、修复技术问题，产出可应用的正文、PR、字段修改或团队交接包。
6. **验证并记录结果。**执行事实、数据、语言和工程检查；在允许范围内发布并回读验证。用真实观测比较前后变化，记录库存、促销、发售和平台变化等影响。
7. **决定保留、回滚或继续试验。**把有效方法及失败经验沉淀为有版本的策略、规则、技能和测试，形成下一批任务。

事实冲突只隔离对应字段；缺少连接只阻塞依赖该连接的动作。其余分支继续执行，避免整个项目停在“等待确认”。

## 品牌与 TA 基线

当前采用用户指定的 [AM marketing planner references](https://github.com/khonsou/CyberboardR6MarketingPlan/tree/4396097272fe7d7455baf85404e594f98d22efb9/am-marketing-planner/references)：品牌、目标人群、产品、方法论及视觉五份资料。原文、提交、来源时间、读取时间与 SHA256 保存在 [来源记录](outputs/brand-context/source-manifest.json)，策划解释与限制在 [品牌上下文](config/brand-context.json)。它是品牌资料来源，区别于通用开源工具及产品事实库。2026-11-01 用户明确更新品牌核心为电竞鼠标与 AI device；该方向优先于旧资料中的“机械键盘为核心”，原文保持留存。

分析先确定 **TA → 需求 → 决策阶段 → 渠道 → 证据 → 产物与验收**，兼顾技术体验、原创设计、工艺与文化、真实社区参与。每轮锁定品牌资料快照；资料更新后旧轮显示原版本或“未采用”，重新分析才采用新版本，不能把历史任务追认为使用了新画像。独立 GEO 回答测试保持中立，不注入品牌定位或画像。

画像是策划定义，未被本项目验证为真实用户分布。参考资料中的历史流量、价格、发货、限量、全球首创及竞品评价不直接进入现行事实或基线；逐型号、批次、市场与日期复核后才使用。无论通用方法还是品牌资料，都不能覆盖既有事实冲突、权限和测量约束。

## Agent 与人类团队如何衔接

默认由 Agent 完成可验证的采集、分析、写稿、翻译、代码修改、测试与结果整理；在已有权限和授权范围内连续执行。团队可以按实际工作方式接管品牌判断、创意、产品决策、实体实验、媒体关系或指定的发布环节。

交接的单位是**带上下文、可直接执行并可回流的任务包**。每个任务包包含：

- 任务 ID、目标需求、优先级及需要团队作出的具体决定或动作。
- 观察证据、来源、适用型号与市场，以及 Agent 已完成的分析。
- 可直接使用的产物，例如内容稿、PR、修改 payload、测试协议或媒体资料。
- 验收条件、依赖、影响范围、回滚办法和接续位置。

团队的决定、修改、实验数据或执行结果回写同一任务与事实记录，Agent 校验后续跑、复测并更新方法。支持 Agent 直接执行、团队执行和混合模式，避免反复转述背景、重复整理资料或丢失反馈。

“已交接”与“已完成”分别记录：完成必须有对应产物与验收证据。与 Issue、PR、CMS 或团队工作系统的双向同步属于后续接入能力；当前以本地任务与文件契约承载。

## 自我优化：改进方法，也改进执行

项目的目标包含两层有证据、有版本、可回滚的改进能力。

### 方法层

检验哪些需求、渠道、来源、内容形式和商品信息改进，能提升品牌的准确呈现、适配推荐和业务结果。每轮保留假设、基线、改动、观察窗口、结果和适用条件；用固定面板、保留题及可比对象检验有效性。

得到支持的方法进入品牌 playbook；未得到支持或带来负面影响的方法保留记录，供下一轮调整。不同市场和平台分别判断，局部经验不直接推广为通用排名规则。

### 执行层

根据失败记录、重试、验收结果、耗时、调用成本及团队反馈，改进任务拆解、工具选择、提取规则、提示词、连接适配和验证过程。代码与工作流改动经过回归和小范围验证，再替换稳定版本；上游升级也需要单独核验。

自我优化的产物是可追溯的策略、规则、技能、代码与测试版本。模型自评分上升不能证明改进；不能通过删除难题、隐藏失败、降低事实标准或擅改目标、权限与预算制造进步。**当前已实现轮次复盘、策略候选版本和下一轮读取经验；策略效果验证、自动修改执行器并经过评估晋升尚未实现。**

## 如何判断成功

- **品牌呈现**：在匹配需求中被发现、被正确描述和适配推荐，关键事实错误得到减少。
- **证据与分发**：有效需求有可核验资料支持，自有与第三方来源、商品数据和渠道信息保持准确。
- **用户与业务结果**：在可观测范围内改善有效访问、考量、购买、候补及支持体验，并明确归因限制。
- **执行质量**：优化任务通过验收，单位有效产出的耗时与成本合理，交接完整、结果能够回流。

官网流量、官网引用率、品牌提及率和内容数量分别解释。可信第三方资料支持的正确推荐也可以是成果；引用官网但说错型号并不构成成功。消费端回答、API 回答和纯检索结果分开统计，失败率与未触发 AI 的测试单列，不生成虚假的零分基线或未来收益。

## 开源基础与选型原则

AM SEO 组合并适配多个开源项目的方法与组件，形成面向品牌的执行与评估体系。**下面是当前按项目适配度选定的组合，不代表已经证明它们在所有场景中最优。**选型与替换依据任务覆盖、可验证性、维护、许可、成本和接入复杂度，而非只看热度。

- **[marketingskills](https://github.com/coreyhaines31/marketingskills)**：借鉴品牌、SEO/GEO、内容和分析任务方法，以品牌事实与实际结果校准建议。
- **[Crawl4AI](https://github.com/unclecode/crawl4ai)**：提供公开页面抓取、渲染及结构化采集基础。
- **[OpenHands Software Agent SDK](https://github.com/OpenHands/software-agent-sdk)**：独立 Agent 的代码、文件、终端与任务执行组件。
- **[GitHub gh-aw](https://github.com/github/gh-aw)**：仓库内的 Agent 工作流、受控写入与 PR 产物路径。
- **[browser-use](https://github.com/browser-use/browser-use)**：需要浏览器规划的已授权界面操作。
- **[Playwright](https://github.com/microsoft/playwright)**：DOM、网络、截图与可重复的浏览器回归。
- **[promptfoo](https://github.com/promptfoo/promptfoo)**：可复现的模型评估底座，需适配真实联网、引用和品牌事实指标。

7 个官方上游已实际拉取；精确 commit、来源、角色和许可在 [版本锁](config/upstreams.lock.json)，checkout 位于被 Git 忽略的 `vendor/`。拉取不等于已安装、运行或完成整合；OpenHands 与 gh-aw 是可选执行模式，现有聊天中的 Agent 也能直接操作本项目。模型、搜索、浏览器和云服务费用与开源许可分开。

## 当前实现与下一阶段

当前已经可用：

- 本机 URL 优化循环：搜索分析、动态任务、Agent 执行与人工结果回流、独立验收、评估、策略候选与下一轮接续。
- 当前方法读取锁定的 marketingskills SEO / AI SEO 资料，实际执行器是本机 Codex CLI；其余上游 checkout 保留为待适配组件，未冒充已运行。
- 3 页原始 HTML 技术诊断、中英鼠标与 AI device 的四题独立 Agent/API 答案面板，以及固定四查询的 Bing 浏览器搜索证据导入；原文、引用、顺序、截图、时间与口径分别保存。
- 本地 CLI、机器任务图、事实与证据记录、离线修改及回滚验证、观测结果计算器。
- 11 条产品事实、13 项离线修改、中英各一份修订稿、48 条未运行的评测题。
- 行为测试覆盖工作流、测量和 API，另有 87 项离线产物检查；以验证命令输出为准，上游版本可独立核验。

接下来按依赖推进：扩展具有代表性的观测与独立证据核验，接入搜索数据及消费端 AI 面板，连接实际发布，再验证策略的效果与执行器改动。持续调度、线上自动优化和团队系统双向同步目前尚未接通。

现有任务图以首批网站与商品事实治理为起点，尚未完整覆盖这里定义的跨渠道范围。后续实现应按本 README 扩展，保留已经完成的证据与验收记录。

## 命令参考

以下供 Agent 与维护者使用。需要 Python 3.11+、Git；浏览器服务及离线命令没有第三方 Python 依赖。

```bash
./am-seo serve
./am-seo status
./am-seo doctor
./am-seo deps verify
./am-seo run --offline
python3 -m unittest discover -s tests -v
```

```bash
./am-seo --help
./am-seo status --json
./am-seo doctor --json
./am-seo validate
./am-seo score observations.jsonl metrics.json
python3 scripts/sync_upstreams.py sync
```

`serve` 启动 `http://127.0.0.1:8787/` 的本机控制台。`run --offline` 重放已有证据、验证修改与回滚；它不是启动持续监控或自主优化的命令。`sync_upstreams.py verify` 离线核对版本与工作区；`sync` 按锁文件恢复 checkout，拒绝修改已有脏仓库。

继续工作前读取 [Agent 约定](AGENTS.md)、[执行入口](outputs/agent-kit/RUN-AGENT.md) 和 [当前任务图](outputs/agent-kit/tasks.json)。凭证保存在运行环境，事实、执行记录和团队回流保留来源与版本；生产修改、账号操作和外部沟通按实际访问与授权范围执行。
